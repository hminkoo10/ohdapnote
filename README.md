# 오답노트 (OhdapNote)

문제집과 답지(PDF 또는 사진)를 **책장에 한 번 등록**해 두면, 학생마다 **틀린 번호만 골라 시험지처럼 깔끔한 PDF**로
묶어 주는 윈도우용 수학 오답노트 프로그램입니다.

- **책장과 학생 오답노트가 따로**: 책(문제집+답지)은 한 번만 올려 분석하고, 오답노트를 만들 때 책장에서 골라 씁니다. 한 오답노트에 여러 권도 됩니다.
- 문제 번호를 자동으로 찾아 **쪽 번호와 함께** 표로 보여 줍니다(단원마다 1번부터 다시 시작하는 책도 OK).
- 4자리 연번(0001…), 예제·유제와 Level 01… 처럼 **번호 체계가 둘 이상 섞인 책**, `[0100~0102] 다음 글을 읽고…` 처럼
  **공통 지문이 따로 있는 문제**(지문을 문제와 함께 내보냄)도 인식합니다.
- **번호가 이어지지 않으면 의심**해서 알려 줍니다: 빠진 번호는 표에 `?` 로, 확인할 쪽은 따로 모아 보여 주고,
  사용자가 직접 보고 **문제없음 / 직접 고치기 / 꼼꼼히 다시 찾기 / Gemini에게 맡기기** 중에서 고릅니다.
- 답지 앞쪽의 **빠른 정답표는 자동으로 건너뛰고**, 단·쪽을 넘어가는 긴 해설도 이어 붙입니다.
- 디지털 PDF는 글자 위치로, 스캔본·사진은 OCR(문자 인식)로 번호를 찾습니다. 인터넷 없이 동작합니다.
  - 휴대폰 스캔 앱·스캐너가 쪽 위에 몰래 깔아 둔 OCR 글자(한글이 엉터리인 경우가 많음)는 믿지 않고 직접 다시 읽습니다.
  - 한 줄에 문항이 둘 이상 나란히 있는 편집(`0001 …   0002 …`), 색 상자 속 흰 번호(`0053 | 대표 문제`)도 찾습니다.
  - 번호가 건너뛴 곳은 해상도를 바꿔 한 번 더 읽고, 그래도 없으면 번호 자리를 하나씩 잘라 숫자만 다시 읽습니다.
- 선택 기능: 무료 **Gemini API**(Google AI Studio) — **1순위·2순위 모델**을 정해 두면 한도가 찼을 때 자동으로 넘어갑니다.
- PDF는 **실제 시험지 양식**(제목, 학원·선생님·학생·점수 칸, 쪽 번호)으로 만들어집니다.
- 설치형 프로그램이며 **새 버전이 나오면 자동으로 업데이트**됩니다.

개발: **구현민**

## 설치

1. [Releases](https://github.com/hminkoo10/ohdapnote/releases) 에서 `OhdapNote-Setup-x.y.z.exe` 를 내려받아 실행합니다.
2. 코드 서명 인증서가 없어서 처음 실행할 때 “Windows의 PC 보호” 창이 뜰 수 있습니다. **추가 정보 → 실행**을 누르세요.
3. 설치가 끝나면 바탕화면/시작 메뉴의 **오답노트**를 실행합니다.

업데이트는 프로그램이 켜질 때(그리고 4시간마다) 자동으로 확인해서 내려받고, 다 받으면 화면 오른쪽 위에
**“재시작하고 설치”** 버튼이 나타납니다. 그냥 두면 프로그램을 끌 때 설치됩니다. (설정 → 업데이트 확인으로 직접 확인도 가능)

## 사용법

### 1. 책장에 책 등록 (한 번만)

1. 첫 화면 **책장** 탭 → **새 책 등록** → 이름 입력 (예: `쎈 수학Ⅰ`)
2. **문제집**과 **답지** 칸에 파일을 끌어다 놓거나 클릭해서 고릅니다.
   - PDF 1개, 또는 사진(JPG·PNG) 여러 장(파일 이름 순서대로 쪽이 됩니다). PDF 여러 개는 이름 순서대로 이어 붙입니다.
3. 칸마다 따로 있는 **[문제집 분석]**, **[답지 분석]** 버튼을 누릅니다. (분석 중에는 **멈추기**로 바로 멈출 수 있어요)
   - **쪽 범위**: 예) `5-180`, `3-10, 15`. 답지는 앞쪽 *빠른 정답* 표를 빼 주면 짝 맞추기가 더 정확합니다.
   - **번호 모양**: 보통 `자동`. 잘 안 잡히면 `1. 2. 3.` / `0001` 등으로 직접 지정하세요.
   - **다음 단·쪽으로 이어짐**: 해설이 다음 단·다음 쪽으로 넘어가는 경우(답지는 기본으로 켜짐).
   - **PDF 1쪽 = 책 ○쪽**: 표에 책에 인쇄된 쪽 번호로 보이게 맞춥니다(쪽번호가 글자로 있으면 자동).
4. **인식 결과** 탭에서 쪽마다 찾은 번호를 확인합니다.
   - **확인이 필요한 쪽**이 위에 모여 나옵니다(번호가 건너뛰었거나 인식이 애매한 쪽). 쪽마다
     - **검토**: 페이지를 보며 직접 고치기
     - **꼼꼼히 다시 찾기**: 그 쪽만 고해상도 OCR + 앞뒤 쪽 번호에 맞춰 더 꼼꼼히 다시 찾기
     - **Gemini**: 그 쪽을 Gemini에게 맡기기 (여러 쪽을 체크해서 한 번에 보낼 수도 있음)
     - **문제없음**: 이대로 괜찮으면 표시 지우기
   - 표에서 `116 ?` 처럼 점선으로 보이는 칩은 **번호 순서상 있어야 하는데 못 찾은 번호**입니다. 누르면 그 쪽이 열립니다.

### 2. 학생 오답노트 만들기

1. 첫 화면 **학생 오답노트** 탭 → **새 오답노트** → 학생 이름·제목을 쓰고 **책장에서 책을 고릅니다**(여러 권 가능).
2. 쪽마다 번호 버튼이 나옵니다. 틀린 번호를 누르세요.
   - 번호에 마우스를 올리면 오른쪽에 문제와 해설이 미리 보입니다.
   - 쪽 번호 버튼을 누르면 그 쪽 문항을 한꺼번에 선택/해제합니다.
   - **빠른 선택** 칸: `12쪽: 3, 5, 7-9` 처럼 쪽과 번호로, 또는 `15, 22` 처럼 번호만 입력.
   - 점선 번호는 답지에서 짝을 못 찾은 것입니다. 미리보기에서 짝을 직접 고를 수 있습니다.
   - 책이 여러 권이면 위쪽 책 탭으로 바꿔 가며 고릅니다.
3. 오른쪽 **시험지로 내보내기**
   - **시험지 머리**: 제목, 학생, 학원, 선생님, 날짜 (학원·선생님 기본값은 **설정**에서 저장)
   - **문제지** / **해설지** / **문제 + 해설(문제마다 바로 뒤에)** / **문제 + 해설(해설은 맨 뒤에)**
   - 1단/2단, 풀이 여백(없음·3cm·8cm·한 쪽에 한 문제), 출처(책·쪽·번호)·새 번호 표시를 고를 수 있습니다.
   - 공통 지문이 있는 문제는 지문을 함께 싣습니다(같은 지문의 문제가 이어지면 한 번만).
   - 원본이 PDF면 글자가 선명한 벡터 그대로, 스캔본·사진이면 고해상도 이미지로 잘라 붙입니다.
   - **파일: 한글(HWPX)** 을 고르면 한글(2014 이상)에서 고칠 수 있는 `.hwpx` 로 저장합니다. Gemini 키가 있으면 문제·해설을
     글자와 **한글 수식**(수식 편집기로 고칠 수 있음)으로 옮기고, 그래프·도형은 잘라서 그림으로 넣습니다.
     키가 없거나 옮기지 못한 문항은 그림으로 들어갑니다. 옮긴 결과는 책 폴더에 저장해 두어 다시 내보낼 때는 묻지 않습니다.

### 인식이 틀렸을 때 – 페이지 검토·수정 (책 화면)

**페이지 검토·수정** 탭에서 쪽마다 인식된 영역이 상자로 보입니다. 왼쪽 목록의 ⚠ / `?n` 표시는 확인이 필요한 쪽입니다.

| 하고 싶은 것 | 방법 |
| --- | --- |
| 번호 고치기 | 상자 클릭 → 위쪽 `번호` 칸에 입력 |
| 영역 옮기기/크기 조절 | 상자를 끌기 / 모서리 끌기 |
| 빠진 문항 추가 | 점선 번호(인식은 됐지만 고르지 않은 후보)를 누르기, 또는 `문항 추가` → 빈 곳을 드래그 → 번호 입력 |
| 다음 단·쪽으로 이어지는 부분 추가 | 문항 선택 → `영역 추가` → 이어지는 부분 드래그 (다른 쪽으로 넘어가도 됨) |
| 삭제 | 상자 선택 → `삭제` 또는 Delete 키 |
| 이 쪽 다시 찾기 | `꼼꼼히 다시 찾기` (로컬) 또는 `Gemini` |
| 이 쪽은 괜찮음 | `문제없음` |
| 쪽 넘기기 | ← → 키 |

책에서 번호를 고치면 그 책을 쓰는 오답노트들의 선택도 같이 따라 바뀝니다.

### Gemini 보조 인식 (선택)

1. [Google AI Studio](https://aistudio.google.com/apikey) 에서 무료 API 키를 만듭니다.
2. **설정**에 키를 붙여 넣고 **1순위 모델**(기본 `gemini-flash-latest`)과 **2순위 모델**을 정합니다.
   `모델 목록`을 누르면 쓸 수 있는 모델이 나오고, 칩을 누르면 1순위, Shift+누르면 2순위로 들어갑니다.
3. 자동 분석은 Gemini를 쓰지 않습니다. 인식 결과의 **확인할 쪽**에서 사용자가 고른 쪽만 Gemini로 보냅니다.
   진행 창에서 쪽마다 결과가 보이고, **취소**를 누르면 보내던 요청까지 바로 끊습니다.
4. **한글(HWPX)로 내보낼 때**도 키가 있으면 내보내는 문항(고른 문제·해설)의 그림을 Gemini로 보내 글자·수식으로 옮깁니다.
   처음 옮기는 문항만 보내고(진행 창·취소 같음), 한 번 옮긴 문항은 다시 보내지 않습니다. PDF로 내보낼 때는 쓰지 않습니다.

- 1순위 모델의 한도가 다 차거나(429) 쓸 수 없으면 자동으로 2순위 모델로 넘어갑니다.
- 무료 등급에는 분당/하루 요청 한도가 있어서, 설정의 `분당 요청 수`(기본 8)에 맞춰 천천히 보냅니다.
- 무료 등급에서는 보낸 페이지·문항 이미지가 Google의 서비스 개선에 쓰일 수 있습니다. 민감한 자료라면 쓰지 마세요.

### 화면

차분한 색에 화면 전환·누름 애니메이션이 들어가 있습니다. 윈도우에서 “애니메이션 효과”를 꺼 두었어도 켜지며,
필요하면 **설정 → 프로그램 → 애니메이션: 줄이기**로 끌 수 있습니다.

## 데이터 위치

`%APPDATA%\OhdapNote\data\` 아래에 저장됩니다. (설정 → 데이터 폴더 열기) 프로그램을 지워도 이 폴더는 남습니다.

- `books\<책 ID>\` — 올린 문제집·답지 사본과 분석 결과(`book.json`), 한글로 내보낼 때 옮긴 글자·수식(`transcripts.json`)
- `notes\<오답노트 ID>.json` — 학생 오답노트(고른 문항, 시험지 머리)
- `settings.json` — 설정

예전 버전(오답노트마다 파일을 따로 올리던 방식)의 `projects\` 데이터는 처음 켤 때 자동으로 책 + 오답노트로 옮겨집니다.

## 자동 빌드·배포 (관리자용)

설치된 프로그램은 이 저장소의 **GitHub Releases** 최신 버전을 보고 스스로 업데이트합니다.
(켤 때와 4시간마다 확인 → 백그라운드로 내려받기 → 오른쪽 위/설정에 **"지금 다시 시작해서 설치"** 표시, 그냥 두면 끌 때 설치)

### 자동 (기본)

**main 에 앱 코드가 바뀌어 올라오면(푸시 또는 PR 병합) 알아서 배포됩니다.**
`Release (Windows)` 워크플로가

1. 버전을 정하고 — 지금 버전이 이미 배포됐으면 patch 를 1 올려 커밋 (`0.1.0` → `0.1.1`)
2. 태그(`v0.1.1`)를 만들고
3. 윈도우 설치 파일(`OhdapNote-Setup-0.1.1.exe`)과 `latest.yml` 을 빌드해 Release 로 올립니다.
4. 업데이트 내용은 지난 버전 이후의 커밋 제목으로 자동 작성되어 사용자의 업데이트 알림에 보입니다.

README·테스트만 바뀐 푸시는 배포하지 않습니다. 첫 배포(v0.1.0)의 업데이트 내용은 `RELEASE_NOTES.md` 를 씁니다.

### 직접 정하고 싶을 때

- **큰 버전 올리기**: GitHub → **Actions** → **Release (Windows)** → **Run workflow** → `minor`(0.1.x → 0.2.0) / `major`(→ 1.0.0) 선택, 업데이트 내용 입력
- **명령으로**: `npm run release:minor` (버전 올려 커밋·태그 푸시 → 같은 워크플로가 배포, 태그 메시지가 업데이트 내용)

> 워크플로가 main 에 버전 커밋과 태그를 올리므로, main 에 "PR 필수" 같은 브랜치 보호를 걸면 자동 버전 올리기가 막힙니다.

> 저장소가 공개(public)여야 설치된 프로그램이 업데이트를 받을 수 있습니다.

`CI` 워크플로는 푸시·PR 마다 테스트를 돌리고, main 이 아닌 브랜치는 시험용 설치 파일을 Actions 의 Artifacts(`OhdapNote-Setup`)로 올립니다.

### 자동 업데이트 동작 확인 (개발자용)

리눅스에서 구버전/새 버전 AppImage 를 만들어 로컬 업데이트 서버로 실제 업데이트를 돌려 볼 수 있습니다.
(`test/update/update-e2e.mjs` 주석 참고) 구버전이 새 버전을 찾아 내려받고, 무결성을 확인해 설치한 뒤 새 버전으로 다시 켜지는지 확인합니다.

## 개발

Node.js 22 이상이 필요합니다.

```bash
npm install
```
```bash
npm start
```

| 명령 | 내용 |
| --- | --- |
| `npm start` | 개발 모드로 실행 (자동 업데이트는 꺼짐) |
| `npm test` | 단위 테스트 (번호 인식·매칭·빠른 선택 등) |
| `npm run test:fixtures` | 테스트용 문제집/답지 생성 — 단순형 + 시중 교재형(쎈·수능특강 편집 구조 재현), 스캔본·사진 (Playwright Chromium, Python Pillow·numpy, poppler 필요) |
| `npm run test:detect` | 단순형 문서로 인식 정확도 확인 (브라우저에서 실제 엔진 실행) |
| `npm run test:books` | 시중 교재형으로 번호 인식·해설 짝·**쪽을 넘어가는 해설**을 자동 채점 (해설 끝에 숨긴 표식으로 확인) |

## 알아둘 점

- 문제집·답지 PDF는 개인 학습용으로만 사용하세요.
- 스캔본은 OCR 때문에 쪽당 2~3초 정도 걸립니다. 진행 중에 취소할 수 있습니다.
- 책마다 편집 모양이 달라 자동 인식이 완벽하지 않을 수 있습니다. **확인이 필요한 쪽**은 꼭 한 번 봐 주세요.
