# 모의고사 파일 가져오기: 논리 API

화면·다운로드·ZIP 일괄 처리는 포함하지 않는다. 호출자가 로컬 파일을 읽고 PDF.js 문서를 `fontExtraProperties: true`로 연다. 정답표는 `getTextContent().items`를 내용 순서로 넘긴다. 쪽별 결과를 과목/선택 키로 병합할 때 충돌을 확인해야 한다.

| 함수 | 입력 → 출력 |
|---|---|
| `identifyExam` (mockexam.js) | `{filename, path, text}` → 시험 종류·시행연도·학년도·월·학년·과목·파일 역할·선택·홀짝·듣기 범위·확신도·이유 |
| `groupExamFiles` | 파일 배열(`metadata` 선택) → 동일 시험/과목/선택/홀짝별 그룹. 미확인 파일은 자동 병합하지 않음 |
| `normalizeHancomText` (hancom.js) | 글자, 선택 글꼴명 → 확인한 PUA 문자 치환. 모르는 코드는 보존 |
| `resolvePdfFontName` (hancom.js) | PDF.js 쪽, TextItem.fontName → 실제 글꼴명 또는 undefined. getOperatorList 이후 조회 |
| `readPageLayer` (pdfmath.js) | PDF.js 쪽, 라이브러리 → 글자·선·도형 좌표 |
| `transcribeParts` | `{layer,rect,place}[]` → 기존 블록. 한컴 math는 `eq`, 문단은 기존 `$…$` 표기와 `low` |
| `importAnswerBlocks` (answer-model.js) | 블록 → 한글 수식 `eq` 런. `review:true`로 확인 표시 전달 |
| `parseAnswerKey` (mockexam-answers.js) | 문자열 또는 PDF.js items, 선택 기본 과목/선택 → `{answers, warnings}` |
| `answerKeyToAnswers` | 파싱 결과, `과목\|선택`, 번호→문항 ID → `{version:1,items:{id:{answer,blocks:[]}}}` |

## 확인 규칙과 제한

### 한컴 구조 조사·복원 (2026-11-09 후속)

실물 첫 쪽에서 전체 그림 폴백 원인 재현: 분수/근호 윗선은 선 경로가 아니라
E06D 글리프(가로 늘임, ink 높이 598~639/1024em). 근호 E05C,
시그마 E067, 큰 중괄호 E078~E07B도 글리프다. 별도 경로는 구분선·그림에도 쓰인다.
첨자는 같은 글꼴의 작은 크기와 다른 기준선으로 찍힌다. 본문 TextItem 단위가 아닌
연결된 수식 글리프 단위로 복원하며, 미해독 연결 성분만 그림으로 보류한다.
설치 글꼴의 bounds는 읽기만 했고 윤곽은 저장하지 않았다.

`hancomEquationRegions(layer, rect?)`는 비교 검토·계측용 연결 성분 API다.
분수, 지수/첨자, 근호, 절댓값/괄호, 극한, 합/적분, 로그/삼각함수,
집합 및 조각 연립 괄호의 기존 위치 복원 경로를 사용한다. 큰 연산자 한계,
벡터·정렬된 행렬·거듭제곱근·큰 연산자 한계도 위치로 복원하며 가짜 좌표로 회귀시험한다.
왼쪽 첨자·불규칙 행렬 등은 아직 구조 검증 미완료다. **모든 한컴 출력에 low를 유지**한다.
eq 생성률은 완전 전사 정확도가 아니다. 본문과 수식의 줄 안 결합도 확인 대상이다.

- PUA 대응 182개는 설치 글꼴 cmap·코드별 렌더 대조. `scripts/inspect-hancom.py`는 글꼴을 읽기만 하며 코드·이름을 출력한다. `--build`는 검토한 대응과 두 글꼴의 cmap을 확인한 뒤 `hancom-map.js`를 재생성한다. 조사용 fontTools는 프로젝트 의존성에 추가하지 않는다. 저장소에 원본 글꼴·윤곽·시험 내용 없음.
- 한컴도 EH와 같은 분수선·첨자·극한 등 위치 복원 경로를 사용한다. 미해독 루트/시그마/행렬/연립 조각 등은 추측하지 않고 원본 영역 그림+`low`로 돌려준다. 현재 한컴 전사 결과는 모두 확인 대상이다. EH 반환 형식은 변경하지 않는다.
- 일반 문자열 정규화에서 글꼴명을 생략하거나 내부 키 `g_d0_f3`를 주면 한컴 대응으로 간주한다. 다른 글꼴 PUA일 수 있으면 `resolvePdfFontName(page,item.fontName)`으로 실제 글꼴명을 전달한다. 미확인 PUA는 삭제하지 않는다.
- 공통 답은 `korean`, `math`, 선택 답은 `korean|화법과작문`, `math|미적분`처럼 분리한다. 변환 시 선택 답과 공통 답을 합칠 수 있다. 배점 없는 자료는 `points:null`.
- 정답 파서는 내용 순서의 번호/정답 쌍 또는 번호/정답/배점 열을 지원한다. 단일 과목이며 같은 높이에 반복된 문항 머리글·배점 열이 있는 items는 좌표로 열을 나눠 선택 제목을 연결한다. 교육청 통합 표·좌표 없는 items는 기존 내용 순서를 유지한다. 이미지 정답표는 읽지 않는다. 정답 충돌·미확인 코드는 `warnings`로 반드시 확인한다.
- 합권·불명 과목은 자동 세트 결합하지 않는다. 일반 숫자만 있는 훼손 표는 복구 보장하지 않는다. 호출자는 예상 문항 수·번호 누락도 확인해야 한다.
- 듣기 범위는 확인된 2003~2027학년도 수능/모평 체제에만 제시한다. 학평이나 체제 미확인 시험은 `null`.
- 해설 문항 분할·화면·일괄 처리는 다음 단계. 실물 문제지 측정 결과는 아래 참고.

`node scripts/check-mockexam.mjs <로컬 정답표.pdf>`로 쪽 1의 과목별 개수·PUA 코드·블록 통계만 점검할 수 있다. 파일 내용이나 글꼴을 저장하지 않는다.

## 후속 실물 계측 (2026-11-09)

### 수식: 생성과 정확도를 구별

9개 문제지 전체 쪽을 읽었다. 국어·영어 6개에는 한컴 수식 연결 성분 0개다.
수식 수의 단위는 **인접한 한컴 글리프 연결 성분**으로, 단독 상수·그림 이름표도 포함한다.
따라서 사람이 세는 독립 수식 개수와 같다고 보장하지 않는다.

| 수학 문제지 | 성분 수 | eq 생성 | 그림 보류 | low |
|---|---:|---:|---:|---:|
| 6월 | 543 | 515 (94.8%) | 28 | 100% |
| 9월 | 488 | 464 (95.1%) | 24 | 100% |
| 수능 홀짝 | 1200 | 1138 (94.8%) | 62 | 100% |
| 합계 | 2231 | 2117 (94.9%) | 114 | 100% |

앞의 9영역 중 그림 없이 출력된 영역은 0/9 → 5/9이나, **완전 전사 정확도로 간주하지 않는다**.
비교 시트는 수학 3종의 1·4·7·10·13·16·19쪽에서 쉬운 성분과 긴/미해독 성분을 섞었다.
이전 제목의 63개와 달리 HTML 실제 표본은 60행이었다(2026-11-09 재확인).
원본 PNG와 `hwpeqview.js` MathML을 Chromium으로 렌더한 PNG, eq 원문, 맞음/틀림/그림 선택 칸을
단일 HTML에 넣었다. 판정은 브라우저 로컬 저장. 자료·렌더 결과는 저장소에 넣지 않았다.
경로: (비공개 로컬 계측 자료).
**비교 시트 정확도는 사용자 검토 전이라 미산출.** 무표시 오전사를 피하려고 모든 한컴 출력 low 유지.
본문과 수식의 줄 안 결합, 조판 순서, 큰 연산자 한계·벡터·행렬은 실물 대조가 더 필요하다.

### 한컴 전사 재검토 (2026-11-09)

| 유형 | 변경 |
|---|---|
| 1 윗줄 | 위쪽 항 없이 아래 글자만 덮는 E06D는 높이를 검증해 `bar {…}`. 아래첨자 포함 범위 보존 |
| 2 각 | U+2220 → `angle` |
| 3 첨자 | 가까운 밑 글자의 크기·기준선 사용. 합의 한계가 오른쪽 항 첨자를 삼키지 않도록 범위 축소 |
| 4 괄호 | 본문 글꼴 괄호도 연결 성분에 포함. 짝을 못 확보하면 해당 성분 그림 보류 |
| 5 표 | 같은 폭의 가로선 3개 이상은 겹분수 변환 전 보류 |
| 6 여러 줄 분수 | 선 연결을 확보하지 못한 다중 줄은 두 개 수식으로 확정하지 않고 원본+low |
| 7 연립 조건 | 분리된 조건을 포함하도록 원본 영역 확장. 독립 성분 전사에서는 연립을 보수적으로 그림+low |
| 8 콜론 | E04F는 기존 대응표에 이미 `:`. 해독기의 ASCII 허용 목록에 콜론 추가 |
| 9 기울임 | 글꼴명뿐 아니라 PDF 텍스트 변환행렬의 shear도 반영 |

`hwpeqview.js`의 `bar`는 짧은 macron 대신 확장 가능한 U+203E overline을 사용한다.
모든 한컴 결과의 확인 표시를 유지한다. 보류 사유는 영역의 `reason` 및 `low.detail`에 남긴다.

#### 실물 측정 범위와 한계

기존 HTML의 **실제 60행**을 원본·수정 전 eq·수정 후 MathML과 각각 대조했다.

## 화면 없는 실행

소스 실행 전용. 배포본은 배치 인자를 무시한다.

```sh
OHDAP_USER_DATA="<사용자 폴더>" electron . --exam-batch "<입력 폴더>" --exam-out "<결과 폴더>" --exam-threads 2
```

리눅스에서는 `xvfb-run -a`로 감싼다. OCR 일꾼 기본 2, 범위 1~8 정수.
표준 출력: 시작·시험 시작/끝·전체 끝 한 줄 JSON. 시험지 글은 출력하지 않는다.
결과: `summary.json`, `books/<책 id>/` (기존 책 저장 파일 그대로).
종료 코드: 0 모두 끝, 1 일부 시험·복사 오류, 2 시작 실패·처리 창 종료.
같은 입력·사용자 폴더로 재실행하면 대기열의 미완료 시험부터 재개한다.
입력 묶음은 실행 중 바꾸지 않는다. 새 묶음은 다른 입력 폴더로 실행한다.
모든 과목 열림. 로그인·클라우드·업데이트 없음. 입력 읽기, 사용자·결과 폴더 쓰기 권한 필요.
입력·결과 폴더는 서로 분리. 동일 사용자 폴더의 앱·배치는 동시에 실행하지 않는다.

정답표·해설 후보는 저장 없이 비교해 문항에 가장 많이 연결되는 한 후보만 저장한다.
연결 수가 같으면 OCR 아닌 글자 후보 우선이며, 전 문항 연결 시 남은 후보는 생략한다. OCR 정답은 확인 표시를 유지한다.
