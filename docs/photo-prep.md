# 사진 전처리 (#16)

휴대폰으로 찍은 교재 사진(펼친 두 쪽, 기울어짐·원근·휨·그림자)을 검출 전에 반듯한 쪽으로 바꾼다.

## 흐름

- 사진은 **가져올 때 한 번만** 보정한다. `files:import`(begin) 로 책 폴더에 복사 → 화면에서 `encodePhoto()` 가 사진마다 `preparePhoto()` 로 보정하고 JPEG(0.92)로 저장(`files:photo`) → 모든 사진이 끝나면 `files:commit` 이 교재 파일 목록을 한 번에 바꾼다. 취소·실패는 `files:discard` 가 이번에 만든 파일만 지운다.
- 보정에 성공한 사진은 보정된 쪽 파일(펼친 사진이면 왼쪽·오른쪽 두 파일)만 남기고 원본 사진은 지운다. 보정할 필요가 없거나(반듯한 스캔, 작은 기울기 <0.7°) 확실하지 않으면 원본을 그대로 한 쪽으로 쓴다.
- 바꾸기는 commit 이 성공한 뒤에만 그 역할의 예전 파일(학원 공간에만 있는 것 포함)을 지운다. 더하기는 예전 파일을 그대로 둔다.
- 파일 목록에 쪽 크기(`width`·`height`)를 저장해서 교재를 열 때 그림을 읽지 않는다. `DocSource` 는 최근 그림 두 장(최대 32MiB)만 메모리에 둔다.
- 이미 넣은 사진은 바뀌지 않는다(저장된 문항 좌표 보호). 보정하려면 사진을 다시 넣는다.
- `detect.js`·`analyze.js`·OCR 엔진·npm 의존성은 바꾸지 않았고 AI 를 부르지 않는다.

## 기법 (널리 알려진 표준 기법만)

1. 긴 변 900px 축소본에서 Otsu 문턱값·채도 제한 → 연결 성분 → 볼록 껍질 → Visvalingam–Whyatt 단순화로 종이 사각형을 찾는다. 면적·경계 대비가 부족하면 보정하지 않는다.
2. 네 꼭짓점 호모그래피와 역방향 bilinear 보간으로 원근·회전을 바로잡는다. 종횡비는 마주 보는 변 길이 평균.
3. 펼친 사진은 종횡비와 가운데 부근 어두운 접힘 선(Hough 탐색, 양옆 그림자·행 지지율 조건)으로 두 쪽을 나눈다.
4. 위아래 종이 경계에 3차 곡선을 맞춰 경계 사이를 수직으로 펴는 marginal dewarping(ScanTailor 계열). 경계가 고르지 않으면 휨 보정은 건너뛴다.
5. 남은 기울기는 수평 투영 프로파일 분산을 최대로 하는 각도로 돌린다(확실히 나아질 때만).
6. 지역 상위 분위수로 조명을 추정해 배경 나눗셈(flat-field)으로 그림자를 덜어낸다. 증폭 상한 1.45.

## 시험

- `node --test test/unit/photoprep.test.mjs test/unit/photo-import.test.mjs`
- `python test/fixtures/make-photo-spreads.py` 로 합성 사진(12MP, +3°/−5°/+8°, 원근·휨·접힘 그림자·배경)을 만든 뒤 `node test/e2e/photo-prep.mjs before|after`. 합성 사진과 결과는 gitignore 된 `test/fixtures/generated/photo-spreads/` 에만 둔다.
- 합성 사진 결과: 보정 전 4/16 문항 → 보정 후 세 장 모두 16/16(번호 위치도 16/16), 쪽 2개·각 2단.
- 12MP 한 장 보정 약 1~3초(가져올 때 한 번).

## 한계

- 실제 사진 원본으로는 검증하지 못했다(합성 사진만).
- 흰 책상처럼 종이와 배경 대비가 낮을 때, 종이가 잘리거나 가려졌을 때, 강한 3D 변형·번들거림·번짐은 보정하지 않고 원본을 쓴다.
- 보정한 쪽은 색·명암이 원본과 조금 다를 수 있다.
